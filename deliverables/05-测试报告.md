## 2. 测试策略

### 2.1 契约测试先行（红测试路标）

项目在骨架阶段（T1）就预埋了四份模块测试（`app/tests/test_models.py`、
`test_events.py`、`test_scene.py`、`test_ui.py`）。此时实现尚未完成，测试必然是红的
——CI 面板上"哪个模块红"就是"哪个模块未完成"的路标（红得指名道姓）；对应模块的
PR 合并时必须让自己那份翻绿。这保证了**测试与实现同步生长**，不存在"先写完代码再补
测试"的环节。

### 2.2 分层红线：models / events 零 Qt 依赖

`app/tests/test_contracts.py` 是 L1 机械红线，在**三平台**上强制执行两条：

1. **零 Qt 红线**：在独立子进程中 `import app.models`、`import app.events`，断言
   `sys.modules` 中不得出现任何 `PySide6` / `PyQt` 模块——算法层与事件层必须可以在
   无显示器的裸机上运行，这是"算法可独立测试"的物理保证；
2. **跨平台路径红线**：扫描 `app/` 全部源码，禁止用字符串拼接 `/` 或 `\` 组路径，
   必须使用 `pathlib`——这是三端通用的机械保证。

### 2.3 golden 事件流：动画可复现性的验收手段

需求 FR-14 要求"同一输入两次运行的步骤序列完全一致"。我们把"一致"落成可机器比对的
形式：`tools/gen_golden_events.py` 把事件层对某个输入产生的完整事件流
（Enqueue / Consume / Fork / Complete / DeadEnd / CycleFound 六类事件按序排列）生成为
`evidence/test-data/*.events.json`。测试时重新计算事件流并与 golden **逐项比对**，
任何调度顺序、分支编号的变化都会被立即发现。

### 2.4 测试数据即素材库（append-only）

按项目规范（AGENTS.md 第二节），每个测试用例以三个文件落库于
`evidence/test-data/`：`.in`（输入）、`.expected`（期望输出，JSON）、`.events.json`
（事件流 golden，仅部分用例有）。测试代码不硬编码输入输出，一律从这些文件读取——
**测试报告的用例表因此与测试代码、素材库三者天然一致**。素材库只进不改，历史用例
永不失效。

### 2.5 CI 两层判定策略

依据 [契约定案](../evidence/decisions/2026-09-15-契约定案.md) 第 9 节，CI 检查分两层：

- **L1-infra**：契约红线（零 Qt、pathlib）+ 文档引用检查（`tools/check_docs.py`），
  三平台**必须全绿**，分支保护强制（不绿禁止合并）；
- **L2-T2 ~ T5**：models / events / scene / ui 四个模块测试 job，
  `continue-on-error`——红 = 该模块未完成的路标，合并自己模块的 PR 时必须翻绿
  （review 人工核对）。

好处：任何人的 PR 不会被别人的未完成模块挡住；模块完成进度在 CI 面板一目了然。

### 4.2 CI 三平台结论

- **L1-infra**：`ubuntu-latest` / `macos-latest` / `windows-latest` 三平台矩阵全绿
  （契约红线 + 文档检查），为分支保护强制项——**任何进入 master 的代码都经过了三平台
  验证**；
- **L2-T2 ~ T5**：四个模块 job 全部翻绿（models / events / scene / ui），表示四个
  模块均已按契约完成并通过各自的验收测试；
- **产物链**：`ci.yml` 的 `build-windows-exe` 在每次 master 推送后构建 Windows 单文件
  产物并附 SHA256；`release.yml` 在 tag 推送时三平台各自构建 + 回归测试 + 空目录启动
  冒烟 + SHA256 自检，随后发布。Release v0.1.0（run 35620768539）三份产物齐备，
  下载后在本机 `sha256sum -c` 逐个校验通过。

L2 各检查的含义重申（见第 2.5 节）：L2 job 设 `continue-on-error`，红只代表"该模块
尚未完成"的路标而不阻塞他人；四个 L2 全绿即 T2–T5 全部验收通过。开发过程中 L2 曾因
基础设施问题整片变红，属真实缺陷，记录于第 6 节缺陷⑤。

### 5.2 复杂度分析与结论

依据 [04-详细设计](04-详细设计.md) 第 1 节：

- Kahn 单次分析（入度、分层、卡住节点）为 **O(V + E)**；
- 全序枚举输出本身就有 Θ(T·V) 大小（T 为合法序总数），枚举全部结果不可能对任意
  大图多项式完成；而精确计数等价于统计偏序的线性扩展个数，一般情形为
  **#P-complete**；
- 因此"极速模式"的工程含义是：**避免构造结果列表**，只走计数状态机。

对照实测：30 节点链 0.061 ms、60 节点链 0.083 ms——节点数翻倍耗时仅增 36%，
与 O(V+E) 的线性预期吻合，远优于 NFR-03"数秒内"的指标（快 4~5 个数量级）。
需要说明的是，全链是计数的最简情形（结果唯一、无分叉）；真正决定耗时的是
**搜索树叶子总数**而非节点数本身，分叉多的图计数会随分支指数增长——这正是软件对
结果条数设置截断上限（FR-17）并以界面不卡死为第一优先级的原因。

## 6. 缺陷与回归

以下缺陷全部来自真实开发过程，均有 CI run 号或决策档案佐证
（主要来源：[发布流水线（Release）](../evidence/decisions/2026-09-21-发布流水线（Release）.md)
第四节、[CI-L2任务缺Qt系统库](../evidence/decisions/2026-09-20-CI-L2任务缺Qt系统库.md)）。

### 缺陷① Windows 构建任务打印中文即崩（UnicodeEncodeError）

- **现象**：Windows job 启动约 10 秒即退出，PyInstaller 根本没跑（run 35617828612）。
- **根因**：Windows 控制台默认代码页 cp936/cp1252，脚本向 stdout 打印中文时抛
  `UnicodeEncodeError: 'charmap' codec can't encode`。本地（Linux，UTF-8 终端）完全
  无法复现。
- **修复**：`tools/build.py` 入口新增 `force_utf8_stdio()`，把 stdout/stderr
  `reconfigure` 为 UTF-8（`errors="replace"`）；smoke 子进程输出显式按 UTF-8 解码。
- **回归**：修复后 Windows 构建通过，产物 `TopoSort.exe` 正常发布。

### 缺陷② Windows 冒烟临时目录清理 PermissionError，构建成功却判失败

- **现象**：Windows 构建本体成功，job 却标红（run 35618645820）。
- **根因**：被 `taskkill` 终止的进程短暂持有 exe 句柄，`TemporaryDirectory.__exit__`
  删不掉目录，抛 `PermissionError: [WinError 5]`，把"构建成功"污染成"步骤失败"。
- **修复**：临时目录改用 `ignore_cleanup_errors=True`，并在终止子进程后留 1 秒宽限。
- **回归**：此后多次 Windows 构建/发布（含 run 35521203523、35620768539）未再复发。

### 缺陷③ release job 缺 `GH_REPO`，三平台构建全绿但发布失败

- **现象**：三平台构建全部成功，仅发布 job 失败（run 35620024862）。
- **根因**：该 job 刻意不做 `actions/checkout`（只要产物不要源码），工作目录没有
  `.git`，`gh` CLI 无法推断仓库，报 `fatal: not a git repository`。
- **修复**：job 级显式注入 `GH_REPO: ${{ github.repository }}`。
- **回归**：Release v0.1.0 成功发布三份产物 + 三份 SHA256（run 35620768539）。

### 缺陷④ 目录体积统计未排除符号链接，macOS .app 报成 271.7 MB

- **现象**：macOS 产物体积统计虚高近 3 倍（271.7 MB，实际 96.9 MB）。
- **根因**：`Path.rglob("*")` + `is_file()` 会**跟随符号链接**，Qt framework 内
  103 个符号链接（如 `Versions/Current → A`）指向的同一实体被重复计入。
- **修复**：统计时排除 `f.is_symlink()`；修正后如实记录为 96.9 MB（实体文件 224 个、
  符号链接 103 个），并写入 `evidence/benchmarks.csv`（`app_unpacked_b=101650598`）。
- **证据来源**：T7 验证阶段自查发现（同上决策档案第四节问题 4）。

### 缺陷⑤ CI 的 L2 任务缺 Qt 系统库（libEGL.so.1），本地与 CI 结论矛盾

- **现象**：本地 `uv run pytest -q` 为 66 passed，CI 上 L1 三平台全绿，但
  L2-T3/T4/T5 全红，且崩在 `pytest_configure`（`ImportError: libEGL.so.1: cannot
  open shared object file`），一个用例都没跑到；退出码 3（内部错误）而非 1（断言
  失败）。详见 [CI-L2任务缺Qt系统库](../evidence/decisions/2026-09-20-CI-L2任务缺Qt系统库.md)。
- **根因**：`ci.yml` 只有 L1 的 infra 任务安装了 Linux 无显示环境必需的 Qt 系统库
  （`libegl1 libgl1 libxkbcommon0 libdbus-1-3`），四个 L2 任务全部缺失；pytest-qt
  插件初始化时 import `QtGui` 即失败。四个 L2 里只有 models（以 `-p no:pytest-qt`
  运行）幸免——恰好反向印证 models 层零 Qt 依赖。
- **修复**：把 Qt 系统库安装步骤补进 `suite-events` / `suite-scene` / `suite-ui`
  三个任务（当前 `ci.yml` 中已可见"L2 共用"注释）。
- **回归**：L2-T2 ~ T5 现已全部翻绿（见第 4.2 节），且当初"修复后 T3/T4 应同时
  转绿"的预测成立，反向验证了该诊断。

### 缺陷共同根因的反思

缺陷①~③的共同背景是"**本地只能验 Linux**"：Windows 控制台编码、文件句柄、
`gh` 上下文这些问题在本机永远复现不了，只能靠 CI 三平台迭代暴露——这正是把三平台
构建放进 CI（而非只做本机构建）的价值所在。缺陷④⑤则是"统计/环境脚本本身也需要
测试"的教训：体积统计函数和 CI 配置的改动，同样要经过产物校验与多 job 对照才能
发现失真。

## 7. 测试结论

1. **功能完整性**：66 个自动化用例全部通过，覆盖正常路径、环检测（含下游连坐）、
   三类坏输入（报行号）、容错解析、大图规模、动画确定性与界面端到端；用例表
   （第 3.1 节）逐条可回溯到 `evidence/test-data/` 与 [02-需求分析](02-需求分析.md)
   的 FR/NFR 编号。需求分析第 7 节的验收标准中，P0 需求已全部由测试覆盖并验证通过；
   P1 需求（容错、泳道上限、仅计数、导出）实现情况已在用例表中如实标注。
2. **正确性口径**：教材标准五节点图 `<A,C> <A,E> <B,C> <C,D>` 的合法拓扑序经全序
   枚举验证为**恰 7 条**，与 golden 文件、单元测试、界面结果流三方一致
   （含 2026-09-19 的 6→7 修正，修正本身也留有决策档案与回归测试）。
3. **三端通用**：L1 契约红线（零 Qt、pathlib）在三平台矩阵上强制通过；Release
   v0.1.0 三份产物（`TopoSort` / `TopoSort.exe` / `TopoSort-macos.zip`）均经
   三平台回归测试 + 空目录启动冒烟 + SHA256 自检后发布，校验和可独立复核。
4. **性能达标**：30/60 节点稀疏图极速模式计数耗时 0.061/0.083 ms（数量级优于
   NFR-03 的"数秒"指标），与算法复杂度分析吻合；结果爆炸场景由截断上限保护界面
   不卡死。
5. **缺陷管理**：开发过程中暴露的 5 个真实缺陷（编码、句柄、CLI 上下文、符号链接
   统计、CI 环境库）全部定位、修复并留档，其中 3 个只能由 CI 三平台发现，验证了
   本项目"CI 两层判定 + 素材库留档"测试策略的有效性。
6. **遗留事项**（如实披露）：Windows/macOS 实机手工全流程验证尚未进行（目前证据为
   CI runner 冒烟 + macOS 包静态结构校验）；macOS 未做正式代码签名/公证（首次打开
   需解除 quarantine，已写入交付包 `readme.txt` FAQ）。此两项建议在后续版本安排
   实机回归。
