## 1. 引言

### 1.1 编写目的

本文档明确"拓扑排序应用软件"要做什么、做到什么程度、以及怎样算做到。它是后续概要设计、
详细设计、编码与测试的唯一需求来源；测试报告中的每条用例都应能回溯到本文的需求编号。

### 1.2 项目背景

拓扑排序解决的是"有先后约束的任务如何排出一个合法顺序"这类问题：学生选课要满足先修关系、
汽车配件装配要满足工序依赖、复杂项目要满足任务依赖。当约束关系较多时，人手工推算既慢又
容易漏解——而很多情况下**合法顺序不止一种**，只看一条结果无法判断排布空间有多大。

本项目要求实现一个**桌面应用**（明确不能是网页形式）：输入先后关系，画出关系图，
**用动画演示排序的全过程**，并给出尽可能多的拓扑排序结果；当约束自相矛盾时须能识别。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 关系 / 先修关系 | 一条有向边 `<a,b>`，表示 a 必须先于 b |
| 拓扑序 | 一个线性序列，满足所有关系中的先后约束 |
| 全序枚举 | 求出**全部**合法拓扑序（不是只求一条） |
| 候选池 | 当前入度为 0、可以被排入的节点集合 |
| 分支 | 在候选池有多个选择时，选不同节点所派生出的不同排序路线 |
| 泳道 | 界面上代表一条分支的水平条，展示该分支的推进轨迹 |
| 环 | 关系互相依赖（如 `<A,B>` 与 `<B,A>`），此时无拓扑序 |

## 2. 用户与使用场景

**目标用户**：学习数据结构与算法的学生、需要梳理先后约束的教学或工程人员。
**使用场景**：

- **S1 课堂演示**：教师输入一个关系集合，投影动画过程，讲解"为什么这一步能选、那一步不能选"。
- **S2 作业校验**：学生算出若干拓扑序，用软件核对是否还有遗漏、是否有非法序。
- **S3 冲突排查**：整理出的约束关系写错了（出现环），软件明确指出环上的节点，便于回查。
- **S4 结果留档**：把关系与全部排序结果导出为文本，附在报告或作业中。

## 3. 功能需求

优先级：**P0 = 必须实现**（缺一项即不满足基本功能需求）；P1 = 功能扩充。

### 3.1 输入

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-01 | 支持在界面文本框中**手工输入**关系，一行一条，采用西文尖括号格式 `<a,b>` | P0 |
| FR-02 | 支持从**文本文件导入**关系；文件编码为 UTF-8 | P0 |
| FR-03 | 输入容错：空白行自动跳过；全角括号 `（）`、全角/半角逗号、省略尖括号的 `a,b` 均可接受 | P1 |
| FR-04 | 重复关系自动去重，不影响结果 | P0 |
| FR-05 | 输入非法时给出**明确错误提示并指明行号**（如"第 2 行解析失败：..."） | P0 |
| FR-06 | 将当前关系**保存为文本文件**，与导入构成往返一致（存进去再读出来内容不变） | P1 |

### 3.2 图形化展示

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-07 | 依据关系自动绘制**有向关系图**，节点**按依赖层次分层**排布（源点在第 0 层） | P0 |
| FR-08 | 画布支持**平移与缩放**，图较大时仍可查看细节 | P1 |
| FR-09 | 节点视觉状态区分：待处理 / 就绪（候选）/ 本拍被选中 / 已消耗 / 卡住 | P0 |
| FR-10 | 候选池以醒目的方式呈现当前所有可就绪节点 | P0 |

### 3.3 排序过程的动画演示（本项目核心特色）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-11 | 「开始」后**动画演示**排序全过程：节点入候选池、被选中消耗、图上同步变化 | P0 |
| FR-12 | 候选池存在多个可选节点时，程序**多路并推**：分出多条分支同时演示，界面上以**泳道**并列展示 | P0 |
| FR-13 | 控制能力：**暂停 / 恢复 / 单步 / 跳完**，以及**速度调节** | P0 |
| FR-14 | 演示须**可复现**：同一输入两次运行的步骤序列完全一致（教学演示不能随机） | P0 |
| FR-15 | 分支数量超过泳道展示上限时，超出部分不单独展示但**仍照常计入结果**，并给出提示 | P1 |

### 3.4 结果输出

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-16 | 列出**尽可能多**的合法拓扑序，每条一行、空格分隔 | P0 |
| FR-17 | 结果数量很大时按上限截断，并显示实际条数，**界面不得卡死** | P0 |
| FR-18 | 支持把结果**导出为文本文件** | P1 |
| FR-19 | 支持**仅计数**模式（只关心有多少种排法，不求具体序列），用于大图快速估算 | P1 |

### 3.5 异常与边界

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-20 | 检出**环**时给出明确提示，列出处于环上的节点，说明不存在拓扑序（不得崩溃、不得给出错误结果） | P0 |
| FR-21 | 边界输入：空输入、单节点、无边（全孤立节点）、全链（唯一序）、稠密分叉（阶乘级爆炸）、多环、自环 | P0 |
| FR-22 | 自环 `<A,A>` 视为非法输入并报错（自相矛盾，见契约定案） | P0 |

## 4. 非功能需求

| 编号 | 需求 | 说明 |

| NFR-01 | **三端通用**：Windows / macOS / Linux 均可运行，代码不得使用平台专属 API（路径用 `pathlib`，读写显式 UTF-8） | 硬性要求，CI 三平台矩阵验证 |

| NFR-05 | **界面可用**：窗口默认 1280×800，三栏布局；动画流畅不卡顿；错误提示可见且指出原因 | 见 06-用户手册 |
| NFR-06 | **可交付**：单文件可执行程序，三端各一份；目标机器无需安装 Python 环境 | 见 07 打包 |
| NFR-07 | **可追溯**：每项决策留档于 `evidence/decisions/`，每个可见功能配截图，测试输入存 `evidence/test-data/` | 项目规范 TOP RULE |

## 5. 数据格式需求

输入输出统一为**纯文本**（教师任务书规定"数据存储：文本文件"）。

**输入**：一行一条关系，西文尖括号。

```
<A,C>
<A,E>
<B,C>
<C,D>
```

**输出**：一行一条完整拓扑序，空格分隔（该图的合法序恰 **7** 条）：

```
A B C D E
A B C E D
A B E C D
A E B C D
B A C D E
B A C E D
B A E C D
```

> 数量口径说明：标准图合法序数为 **7**（2026-09-19 修正，原 6 条漏了 `A E B C D`），
> 依据见 [标准图数量修正](https://github.com/STU-MS/TopoSort/blob/master/evidence/decisions/2026-09-19-%E6%A0%87%E5%87%86%E5%9B%BE%E6%95%B0%E9%87%8F%E4%BF%AE%E6%AD%A3.md)（issue #13）。

格式细节与容错规则以 [契约定案](https://github.com/STU-MS/TopoSort/blob/master/evidence/decisions/2026-09-15-%E5%A5%91%E7%BA%A6%E5%AE%9A%E6%A1%88.md) 第 1、2 节为准。

## 7. 验收标准

1. 用任务书中的课程先修关系示例测试，软件的运算结果正确。
2. 进一步用计算机系学业指南整理的真实课程先修关系作图并导出排序结果。
3. 满足全部 P0 需求；P1 需求实现情况记入测试报告。
4. 考虑突发与不确定情况（非法输入、环、超大规模、空输入）且不崩溃。
5. 三端各有一份可运行产物。
