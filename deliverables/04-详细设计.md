# 04 详细设计

## 1. 算法内核

### 1.1 设计目标

算法内核位于 `app/models/`，负责关系文本解析、不可变图模型、环检测、
最长路径分层、全部拓扑序生成和精确计数。该层不依赖 Qt，供事件层和
界面层通过 `app.models` 的公共 API 调用。

实现遵循 Issue #3，并采用以下已归档结论：

- `evidence/decisions/2026-09-15-契约定案.md`
- `evidence/decisions/2026-09-18-CycleError异常契约.md`
- `evidence/decisions/2026-09-18-标准图拓扑序数量修正.md`

### 1.2 类与模块设计

| 模块 | 类型或函数 | 职责 |
|---|---|---|
| `parser.py` | `ParseError` | 保存行号、原文和错误原因 |
| `parser.py` | `parse()` | 解析文本、去重边、拒绝自环并构造图 |
| `graph.py` | `Graph` | 保存不可变节点集和边集，提供公共查询 |
| `graph.py` | `CycleError` | 表示环图无法完成分层 |
| `enumerator.py` | Kahn 分析 | 计算入度、最长路径层号和卡住节点 |
| `enumerator.py` | 显式栈搜索 | 稳定枚举或只计数全部拓扑序 |

`Graph.nodes` 和 `Graph.edges` 使用 `frozenset`。算法运行时使用局部
邻接表、入度表和栈帧，不修改图对象，因此同一个 `Graph` 可被重复播放
并得到确定结果。

### 1.3 输入解析

解析器按物理行处理输入，空白行跳过。全角括号和逗号先规范化，再接受
以下三种形式：

```text
<A,B>
（A，B）
A,B
```

每个非空行必须恰好包含两个非空节点名。重复关系通过集合去重；
`<A,A>` 作为自环在解析阶段拒绝。格式错误抛出 `ParseError`，其中
`lineno` 从 1 开始，`line` 保留原始文本。

### 1.4 Kahn 图分析

预处理阶段由边集构造按节点名排序的邻接表，并计算每个节点的入度。
所有零入度节点构成初始候选集。处理节点 `u` 时，对每条边 `u -> v`
执行：

```text
layer[v] = max(layer[v], layer[u] + 1)
indegree[v] -= 1
```

当 `indegree[v]` 降为零时，`v` 可继续处理。扫描结束后：

- 所有节点均已释放：图无环，层号即从源点出发的最长路径长度。
- 仍有正入度节点：图有环，这些节点构成 `cycle_nodes()` 返回的
  “卡住节点集”，其中可能包含被环阻塞的下游节点。
- `layers()` 遇到卡住节点时抛出公开的 `CycleError(ValueError)`，
  不返回不完整布局。

单次分析的时间复杂度为 `O(V + E)`，空间复杂度为 `O(V + E)`。

### 1.5 全序枚举

枚举算法把 Kahn 算法中“从零入度候选选择一个节点”的动作扩展为搜索树：
每个候选节点对应一条分支。为避免递归深度限制，搜索使用显式栈。

每个栈帧保存当前候选元组、下一个候选下标，以及进入该层时选择的节点。
一次状态转移包括：

1. 按字典序选择一个候选节点并加入当前路径。
2. 降低所有后继节点的入度。
3. 将新释放的节点并入下一层候选集并排序。
4. 路径覆盖全部节点时输出一份列表副本。
5. 分支结束时弹出栈帧，恢复后继入度和路径。

按字典序深度优先展开前缀树，使 `iter_topo_orders()` 的输出顺序稳定。
`max_count` 在达到指定结果数后立即终止搜索。环图最终会在路径未完整时
耗尽候选，因此不产生结果。

设合法拓扑序数量为 `T`。输出本身已有 `Theta(T * V)` 的大小，所以全部
枚举不可能对任意大图保持多项式时间。

### 1.6 仅计数模式

`count_orders()` 复用同一显式栈状态机，但叶节点只将计数器加一，不复制、
保存或返回完整序列。它降低了结果存储开销，但仍需访问搜索树的每个叶子。

精确统计拓扑序等价于统计偏序的线性扩展，一般情形为 `#P-complete`。
因此“极速模式”表示避免构造结果列表，不表示任意 30/60 节点图都能快速
完成。界面层仍需对高分支图提供截断或用户提示。

参考资料：

- A. B. Kahn, *Topological sorting of large networks*,
  DOI: <https://doi.org/10.1145/368996.369025>
- G. Brightwell and P. Winkler, *Counting Linear Extensions is
  #P-Complete*, DOI: <https://doi.org/10.1145/103418.103441>
