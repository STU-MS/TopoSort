## 一、背景

老师任务书提交材料要求「**所有 doc 文档同时另存为 pdf 文档**」，且交付文档为 Markdown（`deliverables/*.md`、`deliverables/personal/*.md`、`minutes/*.md`）。

原 issue #31 判断本机（当时记录为 Ubuntu 24.04）**无** `libreoffice` / `soffice` / `pandoc` / `antiword`，因此建议走方案 (a)「组员用 Word/WPS 手工另存为 PDF」。

2026-09-25 在交付机（macOS）重新实测，环境与原判断不同，从而出现更优选项。

## 二、实测环境（2026-09-25，交付机 macOS）

| 工具 | 状态 |
|---|---|
| `pandoc` | ✅ 3.11（`/opt/homebrew/bin/pandoc`，外部工具，**非仓库依赖**） |
| Google Chrome | ✅ `/Applications/Google Chrome.app`（支持 `--headless=new --print-to-pdf`） |
| `pdftotext` | ✅ 可用于抽取校验 |
| LibreOffice / texlive（xelatex 等）/ wkhtmltopdf | ❌ 缺 |
| Word / WPS | ❌ 缺（仅有 ONLYOFFICE.app） |

## 三、选项对比

| 方案 | 优点 | 缺点 |
|---|---|---|
| (a) 纯手工 Word/WPS 另存为 | 排版最准 | **本机无 Word/WPS**，实际不可行；5 人协作返工大 |
| **(a') pandoc + Chrome headless 自动转 PDF** | **零新增仓库依赖**、可脚本化、可复现；顺带产 `.docx`；中文用系统字体正常 | 依赖本机安装 pandoc+Chrome（缺失时脚本报错，不影响仓库） |
| (b) 引入 md→PDF Python 依赖（weasyprint 等） | 可进 CI | 违反「新增依赖须先讨论」红线；中文字体/分页风险；已无必要 |
| (c) 标准库自拼 PDF | 零依赖 | 需嵌中文字体，工作量远超收益 |

## 四、结论

**采用 (a')：`pandoc` 将 Markdown 转为独立 HTML，再用 Chrome headless `--print-to-pdf` 生成 PDF；同一流程用 pandoc 顺带产出 `.docx`。**

理由：

1. 已实测跑通：`deliverables/03-概要设计.md` → 3 页 PDF（425,890 B），中文（PingFang）清晰、表格完整、无乱码；`pdftotext` 抽取文本与源文一致，证据见 `evidence/screenshots/PDF转换验证-20260925-1.png`。
2. **不引入任何仓库依赖**：`pandoc`/Chrome 均为本机外部工具，`pyproject.toml`/`uv.lock` 不变，不触碰 AGENTS.md 的新增依赖红线。
3. 可脚本化、结果可复现，符合项目「可复现」最高规则；也同时满足任务书「doc 文档」与「PDF」两种形态。
4. 已知小瑕疵（standalone 模板导致标题重复、默认页眉页脚）在 `tools/make_pdf.py` 中用自定义 HTML 模板/CSS 与 Chrome 参数收口。

## 五、实现

- 新增 `tools/make_pdf.py`：遍历 `deliverables/*.md`、`deliverables/personal/*.md`、`minutes/*.md`（排除 `_模板.md`），
  经 `pandoc -t html` → 自定义模板（`<meta charset="utf-8">` + 中文字体 CSS + 表格/分页样式）→ Chrome `--headless=new --print-to-pdf`；
  输出 `deliverables/pdf/<stem>.pdf`，并用 pandoc 输出 `deliverables/docx/<stem>.docx`。
- 脚本自动定位 `pandoc`（`shutil.which`）与 Chrome（`CHROME_PATH` 环境变量 + 三端候选路径 + PATH），缺失时给出明确报错。
- 该脚本为**开发/交付工具**，不进入 `app/`，不影响「算法零 Qt」「跨平台红线」等产品约束。

## 六、影响范围

- 新增文件：`tools/make_pdf.py`、`tools/package_deliverables.py`、`deliverables/pdf/`（产物，交付用）、`deliverables/docx/`（可选）。
- 不改动任何 `app/` 源码、测试、CI、`pyproject.toml`/`uv.lock`。
- 交付包 `group01.zip` 由 `tools/package_deliverables.py` 组装（见 #31 / #16）。
