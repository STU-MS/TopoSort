## 一、背景

任务书要求提交材料「压缩成一个文件上传 mySTU，命名 group01.zip」。此前打包只能在本机手动跑
`tools/package_deliverables.py`，不可复现、且依赖个人机器安装 pandoc/Chrome。

已有两条流水线：`ci.yml`（代码对不对：契约测试/机械红线）、`release.yml`（三端二进制产物）。
本次要新增的是**文档交付包**的流水线。

## 二、结论

**新增独立工作流 `.github/workflows/deliverables.yml`**，不改动 `ci.yml`/`release.yml`：

- **触发**：`workflow_dispatch`（手动预演）+ `push: tags: ['v*']`；
- **权限**：`contents: write`（发布 Release 需要）；
- **`package` job（ubuntu-latest）**：`actions/checkout@v4` → `apt-get install pandoc fonts-noto-cjk`
  → 环境自检（pandoc / `google-chrome --version` / `fc-list :lang=zh`）→ `python3 tools/make_pdf.py`
  → `python3 tools/package_deliverables.py --rebuild` → `sha256sum group01.zip > group01.zip.sha256`
  → `actions/upload-artifact@v4`（`if-no-files-found: error`，保留 14 天）；
- **`release` job（仅 tag）**：`actions/download-artifact@v4` → `sha256sum -c` 自检
  → `gh release view "$TAG" || gh release create ... --generate-notes` → `gh release upload ... --clobber`。

## 三、理由与关键取舍

### 决策 1：单独一个 workflow，不塞进 ci.yml / release.yml
`ci.yml` 管「代码对不对」，`release.yml` 管「三端二进制」。本文件管「文档交付包」，
触发条件与权限需求都不同；且它要装字体、跑 Chrome，较慢，不该拖累每个 PR 的 CI。

### 决策 2：零第三方 Action、零新增仓库依赖
- 只用 GitHub 官方 Action（`actions/checkout`、`actions/upload-artifact`、`actions/download-artifact`）；
- 发布用 runner 自带的 `gh` CLI（延续 `2026-09-21-发布流水线（Release）.md` 的纪律）；
- `pandoc` / Chrome 是 **runner 环境工具**，不进 `pyproject.toml`/`uv.lock`，符合「依赖只从 pyproject/uv.lock 走」。

### 决策 3：直接 `python3`，不 `uv sync`
`tools/make_pdf.py`、`tools/package_deliverables.py` 只用标准库；`uv sync` 会白等 PySide6（约 250MB）。
故 CI 用系统 `python3` 运行这两个脚本。

### 决策 4：必须安装 `fonts-noto-cjk`
ubuntu runner 默认无中文字体，缺了它 PDF 中文会变成豆腐块（□□□）**且不报错**——静默产出坏 PDF。
`make_pdf.py` 的 CSS 字体栈已含 `"Noto Sans CJK SC"`，装包即命中。

### 决策 5：CI 下给 Chrome 追加 `--no-sandbox`
CI runner 常以 root 运行，Chrome 的 setuid sandbox 不可用会直接拒绝启动。
`tools/make_pdf.py` 检测到环境变量 `CI` 时追加 `--no-sandbox`；本地（无 `CI`）保持默认沙箱，行为不变。

### 决策 6（已知取舍）：CI 产出的 zip **不含演示视频**
演示视频 >50M，已 gitignore，不在仓库内。因此 CI 的 `group01.zip` 只含文档 PDF/Word + 源码快照，
用于**自动校验与分发**；最终带视频的提交包仍由本机 `tools/package_deliverables.py` 组装。
不采用「Git LFS 存视频」或「从 Release 下载视频再打包」——复杂化，且视频是一次性录制。
