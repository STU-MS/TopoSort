# 会议记录改用老师下发的《会议记录》模板（docx 原地填内容 + 同版式 PDF）

- **日期**：2026-09-26
- **参与人**：黄应辉（组长，HandyWote）、冯思语（Frieda-Feng，需求/手册）
- **对应 issue**：STU-MS/TopoSort#44（标签 `discussion`）
- **关联留档**：`evidence/decisions/2026-09-26-报告改为模板docx交付.md`（报告那条线，同一类问题）、#43

## 背景

任务书《提交材料》含「会议记录」，老师在 `docs/` 下发了固定表单 `meeting-minutes-template.doc`。
原实现是 `minutes/*.md` → pandoc → docx/PDF：**字段与内容已对齐模板**（每份都写了
`编号/日期/第几组/主持人/会议主题/开始时间/结束时间/参加人员/记录人员/记录时间` +
`会议内容/已解决问题/待解决问题/备注` 四个区块），但**版式不是老师那张表**：标题字号、
下划线字段行、标签格底纹、12 行表格网格都没有。

这与报告那条线（#43：六份合一为「套老师 report-template 的单份 docx」）是同一类形态问题——
老师的规矩是「所有 doc 文档同时另存为 pdf 文档」，形态要求就是**用他给的模板**。

另外确认：老师下发的模板类文件**只有 2 个**（`docs/` 下共 3 个文件，另一个是任务书）：

    docs/assignment.doc                任务书
    docs/report-template.doc           项目报告模板
    docs/meeting-minutes-template.doc  《会议记录》模板
    → 没有「个人任务及感想」模板（任务书只写「每个人都要写」），那份继续走 pandoc 链路。

## 选项

| 方案 | 优点 | 缺点 |
|---|---|---|
| (a) 维持 md → pandoc | 不动能跑的产线，CI 直接出 docx+PDF | 版式不是老师的表单，与报告线形态不一致 |
| (b1) docx 套模板 + 组长手工导出 5 份 PDF | docx/PDF 都是模板真身 | 5 份 × 手工导出；PDF 与 docx 同步靠人；本地与 CI 都不能自动复现 |
| **(b2) docx 套模板 + PDF 用「同版式 HTML/CSS → Chrome 打印」** | docx 是模板真身；PDF 与 docx 同源同版（同一份解析结果、同一套量值）；本地与 CI 全自动、可复现、可亲眼验收 | PDF 不是 docx 的直接导出件（同一内容、两个渲染器） |
| (c) CI 用 LibreOffice 把模板 docx 转 PDF | PDF 直接来自 docx | 本机 macOS 无 `soffice`，本地无法验证；字体替换与域行为不可控；新增重型外部依赖 |

## 结论（采用 b2）

1. **会议记录 docx 在老师模板副本上原地填内容**（与报告同一套做法）：
   `docs/meeting-minutes-template.doc` --(x2t)--> `minutes/template.docx`（入库，支持
   `--refresh-template` 重转）--(fill)--> `deliverables/docx/2026-*.docx`。填
   `编号/日期/第 N 组` + 7 个字段 + 4 个区块正文，样式（9pt 编号行、18pt 标题、华文楷体
   下划线日期行、12 行表格、标签格底纹 `99ccff`、12pt 单元格文字）全部继承模板。
2. **PDF 用同版式 HTML/CSS 由无头 Chrome 打印**（复用 `tools/make_pdf.py` 的
   `find_chrome()` / `html_to_pdf()`），产出 `deliverables/pdf/2026-*.pdf`。
3. **两条渲染线共用 `tools/minutes_data.py` 这一份解析结果**（`Minutes`/`Block`/`Inline`），
   字段与正文逐块一致；解析器是唯一入口，两个渲染器只读不算。
4. **`tools/make_pdf.py` 不再处理 `minutes/*.md`**；CI 在 `make_pdf.py` **之前**新增一步跑
   `build_minutes.py` + `minutes_html.py`。提交目录仍由 `build_submission.py` 从
   `deliverables/{docx,pdf}/` 复制，无需改动。
5. 若日后要「PDF 直接由 docx 导出」，备选路线是 CI 用 runner 预装的 LibreOffice
   （`soffice --headless --convert-to pdf`）；不作为首选的原因见上表 (c)。

## 实测记录（关键坑，勿踩）

1. **模板实测量值**（x2t 转出的 docx 逐块量得）：A4 `pgSz 11906×16838 twips`，页边距
   左右 1800 / 上下 1440；三行表头 = 9pt 右对齐「汕头大学计算机系／编号：」、18pt 居中
   「会议记录」、10.5pt 华文楷体下划线「日期：… 第  组」；12 行 6 列表格（网格
   1368/2160/732/1093/1038/2131 twips、`tblLayout=fixed`、全边框 `sz=4`），**标签格
   `w:shd fill="99ccff"`、单元格文字 12pt**；6 个页眉页脚部件全空。
2. **`x2t` 偶发 `Couldn't create temp folder`**：重试或换输出目录即可（同一命令换 cwd
   实测一次失败一次成功）。它输出的 zip **压缩时间戳与条目顺序不稳定**，要做到
   「幂等可复现」必须确定性重打包（时间戳钉死 1980-01-01 + 条目按名排序）。
3. **「第  组」只能填序数**：整串塞「第一组」会渲染成「第 第一组」（重复「第」）。
   正确做法是取 `第(.*)组` 的序数填进下划线空位：`第 一 组`；PDF 侧在日期行右侧写
   「第一组」，两边读起来一致。
4. **判定「内容完整」必须逐块比对**：先剥 XML 标签、再 `html.unescape`、再空白归一，
   否则 `<a,b>`（被转义成 `&lt;a,b&gt;`）会被误判成缺失。
5. **`make_pdf.py` 必须先摘掉 minutes**：否则 pandoc 会覆盖掉模板版式的产物（实测 5+5 份
   mtime 被改写）；CI 里会议记录两步必须排在 `make_pdf.py` 之前。
6. **PDF 侧不要用等宽字体渲染行内 `code`**：Menlo 与 CJK 回退混排会让 Chrome 在 PDF 里把
   该 span 拆成多个 run，`pdftotext` 结果错位（内容核对会假报缺失）；改
   `font-family: inherit` 后 160/160 全命中。
7. **行高与跨页**：模板原有的 `w:trHeight` 改成 `hRule="atLeast"` 并确保没有 `cantSplit`，
   否则长正文会被裁断或整行推到下一页。

## 验收与证据

- 机械验收：`uv run python tools/check_minutes.py`（9 项：成对性 / docx 字段与四区块逐块完整 /
  字段值格逐格精确相等 / 模板保真（部件集、纸张边距、12 行、`99ccff` 底纹、`atLeast`、无
  `cantSplit`）/ 表头无重复「第」/ PDF 页数与 A4 与文本完整 / docx↔PDF 内容一致 / 副本逐字节一致 /
  表格 run 回归护栏（值格 `jc`、run `sz=24`+楷体、无等宽残留））。当前 **0 不合格、0 告警**。
- 验收器做过**负向控制**：把产物改坏（删 `jc`、改成 `both`/`justify`、`sz=24`→`21`、楷体→宋体、
  删 `rPr`、改标签文字、注入 Consolas 等）均能被抓到。
- 成品截图：`evidence/screenshots/会议记录-docx版式-20260926-1.png`（word 侧）、
  `会议记录-pdf版式-20260926-1.png`（PDF 侧）。
- 遗留未核验：真实 Word/WPS 的分页与打印效果（本机无 Word，跨页判断基于 officecli/LibreOffice 内核）。

## 已接受的偏差（验收时记录，不改）

1. **会议记录正文保留仓库内引用**（`docs/assignment.doc`、`evidence/decisions/*.md`、issue/commit
   号、Release 链接）。理由是 AGENTS.md 要求「决策必须留档、可复现」，会议记录是留档线索的
   主要载体；老师模板未禁止。若日后要改成面向读者的描述，应改 `minutes/*.md` 源文件
   （而不是渲染器）后重跑 `build_minutes.py` + `minutes_html.py`。
2. **docx 与 PDF 是两个渲染器**（模板原地填内容 vs 同版式 HTML 打印），行内等宽、段内对齐
   等细节可能微差；已把 `code` 统一为正文体（两侧一致）。具体一处：值格对齐 docx 依模板
   （开始时间/参加人员/记录人员/记录时间 居中，主持人/会议主题/结束时间 左对齐），PDF 统一
   左对齐；不影响内容与交付。
3. **长会议记录在 docx 里整行跨页**（如 09-15「会议内容」41 块）：XML 里内容只出现一次
   （已机械校验），officecli 预览会在分页处重画行首；真实 Word/WPS 的打印效果未能在本机核验。
