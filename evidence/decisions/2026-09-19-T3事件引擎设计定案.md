## 1. 环图的事件表现：步进到卡死再报

- 分支正常逐步推进；某分支无候选（frontier 为空）且仍有剩余节点 → 发 `DeadEnd(branch_id, stuck_nodes)`，该分支终止。
- **全部**分支终止后，若有分支发生过卡死 → 发一条 `CycleFound(stuck_nodes)`，值为各分支卡住节点的并集（等价于环及环下游节点集；frontier 空 ⟺ 剩余节点全部入度≥1，故 stuck_nodes = 该分支剩余节点全体，数学自洽）。
- **CycleFound 拼在使全部分支终止的最后一拍事件列表末尾、同拍置 `finished`**（否则消费方 `while state != "finished": tick()` 会漏收该事件）。
- 纯环图（如 `<A,B><B,A>`）：分支 0 第一步即卡死，序列为 `[DeadEnd(0,{A,B}), CycleFound({A,B})]`。
- 后台分支卡死的处置见 §3（不发 DeadEnd 事件、计入并集）。

## 2. Fork / Enqueue 微观语义（严格按 T1 契约字面）

- 候选选择顺序：**字典序**（与契约 §3 `iter_topo_orders` "按字典序稳定产出"一致），确定性由此保证。
- 某步候选 frontier 有 k 个节点（k≥2）：原分支按字典序选最小者（`Consume`），并为其余 k-1 个备选各开一条新分支、各发一条 `Fork(branch_id, new_branch_id, node=原分支所选节点)`（截断场景的例外见 §9 前置保险丝）。
- **新分支首次推进必须消费其 Fork 时绑定的备选节点**（不重新按字典序自选）——否则所有分支收敛到同一条序，Complete 恒为 1（已模拟证明只有"绑定备选"解读得到 7 次 Complete）。
- `Enqueue(node, branch_id)` 仅在节点**首次进入该分支候选池**时发（不重复端上桌）；新分支被调度时对其 frontier 重新 Enqueue（Enqueue 按"分支"计，池是每分支独立的）。
- branch_id 从 0 起、Fork 递增分配（契约 §3 已定）。

## 3. 泳道溢出与晋升：动态晋升（拍末补位）

- 任一时刻可视化泳道 ≤ `lane_limit`（默认 8）。
- **活跃集合 = 拍首快照**：当拍只推进拍首已活跃的分支；本拍 Fork 出的新分支、本拍晋升的分支都**下一拍才推进**（每分支每拍至多一步）。
- **拍末补位**：tick 内先按 branch_id 升序推进拍首快照中的活跃分支；拍末若有泳道空出（Complete/DeadEnd 释放），后台队列中 branch_id 最小的分支晋升，其**补发 Enqueue**（该分支在后台期间从未发过事件，故为首次进池，非重复）拼在本拍事件列表末尾；晋升分支下一拍正常推进。
- **泳道分支不降级**，仅终止释放；后台分支一旦晋升不再回后台。
- **后台分支**：不发 Enqueue/Consume/Fork/DeadEnd 可视化事件，但照常推进；**Complete 照发**（计数与结果列表不受影响，契约 §4 原文如此）；若卡死，其 stuck_nodes 照常计入 CycleFound 并集。

## 4. Timeline 状态机：防御式边界行为

正常转移（契约 §4 + T1 预埋测试已定）：`running →(pause) paused →(resume) running`；tick 推进至全部分支终止 → `finished`。

| 调用 \ 当前状态 | running | paused | finished |
|---|---|---|---|
| `tick()` | 正常推进一拍 | 返回 `[]`（空操作） | 返回 `[]` |
| `step_once()` | 先自动 pause，再走一拍并返回该拍事件列表 | 走一拍，保持 paused | 返回 `[]` |
| `pause()` | → paused | 幂等 | 幂等 |
| `resume()` | 幂等 | → running | 幂等 |
| `set_speed(ms)` | 生效 | 生效 | 生效（无视觉后果） |

- `Timeline.player_state_completed() -> list[tuple[str, ...]]`（T1 预埋测试已定名，**归属 Timeline 的公共方法**）：只读视图，返回至今已完成拓扑序，按完成顺序排列；后台分支的 Complete 一并计入。`app/events/__init__.py` 的 API 文档随实现同步补录。
- 验收测试须覆盖上表全部格子（"状态机转移全覆盖"）。

## 8. 调度与确定性总则（v2 新增）

- **iter_events() 全局顺序 = 逐拍交错**：等价于"无泳道上限的 Timeline 逐 tick 拼接"。player 与 Timeline 共用同一套步进内核，两种口径天然一致、golden 可互验。
- **内核 + 调度分层**：`TopoPlayer` = 步进内核（内部维护显式分支工作队列，提供按分支步进与状态快照的内部接口；`iter_events()` 是其无上限封装）；`Timeline` 独占调度权（lane_limit、后台抑制、拍末晋升），但**只做调度决策、不凭空合成事件**——事件内容一律由内核接口产生（含晋升补发 Enqueue），保证"事件流里每一条都来自算法真实步进"。
- **集合遍历总则**：一切集合的遍历与事件发射顺序（同一步解锁多个节点的 Enqueue 成组顺序等）一律 `sorted()` 字典序。理由：Python set/frozenset 迭代顺序受 `PYTHONHASHSEED` 影响，跨进程/跨平台不固定——不排序则"同输入两次播放逐项相等"在 CI 三平台上偶发翻红。

## 9. 规模防护：max_completes 截断参数（v2 新增）

- `TopoPlayer(graph, max_completes: int | None = None)` 与 `Timeline(..., max_completes=None)`（默认 None = 不截断），**现在就进公共 API**。
- 语义：累计 Complete 数达到 `max_completes` 后内核立即停止推进（不再发任何事件、不再 Fork），Timeline 置 `finished`；已得完整序保留。与 T2 `iter_topo_orders(max_count)` 截断语义对齐（`.expected` 用 `orders_capped` + `count` 表达）。
- 动机：T9 用例族含"稠密分叉（阶乘爆炸截断）"与 30/60 节点大图；接口现在加是默认参数，事后加则改已公布的构造签名（契约级变更）。泳道上限不减少计算量（后台分支照跑），截断才是真正的保险丝。
- **前置保险丝（v4，终审发现）**：仅按 Complete 计数点火在宽并行图上过晚——逐拍交错下首条分支需 n 步才 Complete，此前分支已按组合数爆炸（实测 30 节点双链 26s 零产出）。修复：**Fork 前检查"已完成数 + 活跃分支数 ≥ max_completes 即不再开新分支**（每条活跃分支至多 1 个 Complete，上界自洽）；不改变既有事件语义，golden 不变，cap=None 不受影响。discussion issue 由 T3 负责人提交，待组长确认后补编号。
