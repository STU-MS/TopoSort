# 2026-09-27 提交包 group01.zip 内容定案：加可执行程序/测试用例/视频走 LFS，去 docx/sha256/提交说明

## 一、背景

任务书「提交材料（压缩成一个文件）」共 7 项（报告 / 源程序+readme / 会议记录 / 其他项目文档 /
个人任务及感想 / doc 另存 pdf / 演示视频 ≤50M），命名 `group01.zip` 上传 mySTU。
此前 `group01.zip` 由 `deliverables.yml` 在 CI 打出（**无视频、无三端二进制**），视频与二进制
只在 GitHub Release 资产里；组长要求**完整提交包完全由 CI 打出**，本地不再打包。

- **日期**：2026-09-27 · **决策人**：组长（HandyWote）· **参与人**：组长会话内 AI 编码代理（经组长确认）
- **关联**：Issue #46；前置决策 `2026-09-25-交付打包流水线.md`、`2026-09-26-报告改为模板docx交付.md`

## 二、选项

| 选项 | 内容 | 问题 |
|---|---|---|
| (a) 维持现状 | CI 包不含视频/二进制，本机重打包后覆盖 Release 资产 | 本地多一步；CI 包“不合格” |
| (b) 视频入 LFS + CI 注入二进制 | CI 一次打出**完整骨架**的包并传 Release | 需改两个 workflow + LFS |
| (c) 视频/二进制全塞普通 git | 仓库膨胀 160MB+，clone 慢 | 违背“大文件不入 git”约定 |

## 三、结论（组长逐条确认）

### 包内骨架（8 项，约 171MB）

```
group01/
├── 00-项目报告.pdf              （有 pdf 就不留 docx）
├── readme.txt
├── 可执行程序/                  （TopoSort.exe 46M / TopoSort-macos.zip 34M / TopoSort 63M）
├── 会议记录/                    （5 份 pdf）
├── 个人任务及感想/               （5 份 pdf）
├── 测试用例/                    （12 个可导入 txt + 说明.txt）
├── 演示视频/                    （演示视频-Group01.mp4，19.2MB）
└── 源程序/                      （git 跟踪文件全量快照，原样不动）
```

### 明确去掉

1. **全部 docx**——有 pdf 就不留 docx（报告/会议记录/个人感想共 11 份 docx 不进包）
2. **全部 `.sha256`**——包内不带校验值（Release 资产侧的 .sha256 保留）
3. **`其他项目文档/`**——六份合一进报告（决策 2026-09-26：01–06 退出交付清单）
4. **`提交说明.txt`**——不放进包（清单只在打包脚本的控制台输出里）

### 其他决定

5. **演示视频入 git LFS**（19.2MB）：`.gitattributes` track `submission/演示视频/*.mp4`。
   LFS 配额**按账号/组织算**（存储 1GB、带宽 1GB/月，公开仓库免费）：STU-MS 是组织，
   与组长个人名下仓库的额度互不影响。CI checkout 加 `lfs: true` 即可拿到真视频。
6. **测试用例/ 入普通 git**（共约 50KB 小文本）：从 `evidence/test-data/*.in` 精出 12 个
   唯一输入（去重 `001-标准五节点.in` == `001-标准五节点图.in`），改名
   `NN-中文说明.txt`，配 `说明.txt`（每个文件测什么、期望什么，含环/自环/非法格式等反例，
   呼应任务书“突发情况与不确定情况”）。source of truth 仍是 `evidence/test-data/`。
7. **三端二进制由 CI 注入**：release.yml 新增 `package` job（needs: build+release），
   `download-artifact`（pattern `TopoSort-*`）→ 拷进 `submission/可执行程序/` → 打包。
8. **tag 仍由组长手动打**，本次发 **v1.0.1**（v1.0.0 留作历史，不重建）。

## 四、理由

- **“可运行”是现场验收判据**：包内带三端单文件产物，验收机不装 Python/不联网也能跑；
  Windows exe 对应老师最可能用的平台，macOS/Linux 对应组内开发机。
- **测试用例可导入**：老师拿到包就能用任务书图1 / 学业指南数据复跑验证正确性
  （图1 精确 1,566,180 条；学业指南 44 门课 86 边约 10^41 量级）。
- **有 pdf 不留 docx**：避免同一文档双格式重复交付；docx 源仍在仓库与 源程序/ 快照外
  的 deliverables/docx/ 里（不入包但可追溯）。
- **CI 全自动**：打 tag → 三端构建 → 注入 → 完整包上传 Release，人工只剩 mySTU 上传。

## 六、已接受的偏差

- `源程序/` 快照里仍含 01–06 的 md 源稿与 `deliverables/personal/*.md`（组长明确“源程序目录不动”）。
